Epic Goals
📷

Attach & Render Screenshots

Insert and display image attachments inside issue descriptions and comments from both CLI and desktop.

💾

Local-First Storage

Assets stored on the local filesystem by default under .fp/assets/ with content-addressed SHA-256 naming.

🔃

Out-of-Band Sync

Sync binary assets to remote object storage independently of Yjs issue sync frames — no binary blobs in WebSocket protocol.

📄

Markdown Source of Truth

Use fp-asset://<id> logical URIs in markdown. Shared resolver renders consistently across all surfaces.

Key Architecture Decisions
🗃

Content-Addressed Storage

Binary files stored under .fp/assets/ with SHA-256 hash filenames and MIME/size metadata in SQLite.

🔗

Logical URI Scheme

fp-asset://<asset-id> replaces raw file:// URLs in markdown for portable, resolver-agnostic references.

📈

Derived Asset Indexes

Local and remote tables track which issues/comments reference which assets — driven from Y.Doc state, not command handlers.

🔒

Authenticated Asset API

Project-scoped upload/download via Worker routes backed by R2 object storage. Separate from WebSocket Yjs protocol.

🔄

Sidecar Reconciliation

Asset reconcile pass runs after issue sync converges. Upload/download queue handles races and retries independently.

🎨

Shared Markdown Resolver

One resolver pipeline for fp-asset:// refs across desktop, fp-ui review, and console — no per-surface forks.
